# 博物館 VR 開發交接

更新於 2026-11-16（新加坡時間）。專案位於 `E:\unity project\game4026`，使用 Unity `6000.6.7f1`、XR Interaction Toolkit `3.6.1`、OpenXR `1.18.0`、Meta XR Core SDK `209.0.0` 和 URP `17.6.0`。

## 場景與操作

主場景是 [Museum.unity](../Assets/Scenes/Museum.unity)。玩家從博物館西側互動展區前方出生。Hierarchy 的 `Interactive Exhibits` 是四個展區的根物件，位置為 `(-20, 0, -6)`。`XR and Feedback` 包含 XR Origin、XR Interaction Manager 與 `Interaction Services`。

- Quest 3 用握把鍵抓放，扳機使用手電筒與射線工具。一手握弓，另一手靠近弓弦後抓住並拉放。
- 左手 **X** 按一次蹲下，再按一次站起。完整行程為 **50 公分**，相機、Meta 雙手及抓取點共用 `Camera Offset`。真人彎腰和蹲下也會繼續更新追蹤姿勢。
- 左右手的拾取範圍均為手掌抓取點周圍 **7.5 公分**。武器落地後可伸手重撿。
- 無頭盔時，Unity Editor 會啟用桌面模式。點進 Game 視窗後，用 **WASD** 移動、滑鼠右鍵拖曳轉視角、**Tab** 切手、**方向鍵／R／F** 移手、**Q** 抓放、**E** 使用、**Shift** 加快移手。桌面模式有自己的模擬拾取半徑。驗收 Quest 的抓取距離時使用 Near-Far Interactor。

## 驗證與接續

- Quest Link 實測中，左手 X 的蹲下與站起都到達完整行程，追蹤空間下降與回升 50 公分。較早一輪已確認須貼近道具才能抓取。落地重撿與食指最終貼合仍待下一輪真機確認。
- Unity Museum 模擬中，已用左右手撿回落地的斧頭與小刀，遠距離嘗試被拒絕。以兩手同時持斧頭和鏟子驗證物理接觸與衝量、手的視覺握點，以及放手後恢復重力。武器碰撞修正尚待 Quest 真機複測。
- 前一輪共通互動回歸的 42 項 Edit Mode、8 項 Play Mode 測試通過。專用測試場景是 [InteractionTest.unity](../Assets/A_VRInteraction/Scenes/InteractionTest.unity)。使用 [InteractionTest 操作指南](InteractionTest.zh-TW.md) 找測試入口，遊戲介面定義在 [Contracts](../Assets/_Game/Scripts/Contracts/)。
- 若要排查地板高度，先在 Quest 的 Boundary 確認實際地板高度，再站直開 Play。若蹲下後手仍夠不到地板，記錄 `MuseumEyeHeight` 的 `floorCorrection`、`Camera Offset` 的 Y 值，以及手掌抓取點到道具 Collider 的最近距離。

## Android 建置

Quest 獨立版使用 Android、OpenXR、ARM64 和 IL2CPP。[MuseumAndroidBuild.cs](../Assets/A_VRInteraction/Editor/MuseumAndroidBuild.cs) 明確指定 `Assets/Scenes/Museum.unity` 為唯一場景，APK 的套件 ID 是 `com.game4026.museum`。專案預設場景清單仍包含 `SampleScene.unity`。

在專案目錄執行 [Build-MuseumQuest.ps1](Tools/Build-MuseumQuest.ps1) 可產出 Quest 3 版。腳本使用 PowerShell 7 和 Unity CLI，並在 `Library/MuseumQ` 建立獨立建置專案。首次建置前，在 Unity 開啟主專案一次以解析 UPM 套件。

```powershell
pwsh -NoProfile -File 'Docs/Tools/Build-MuseumQuest.ps1'
```

- [MuseumQuestTextures.cs](Tools/MuseumQuestTextures.cs) 在獨立建置專案的 glTFast 匯入階段壓縮 `Assets/Models` 內 GLB 的嵌入貼圖。文物和武器用 ASTC 4×4，環境和展示櫃用 ASTC 6×6。匯入會檢查尺寸、mipmap 數量與 sRGB 設定，原始 GLB 及場景保留原檔。
- Quest 建置會暫時關閉 Google Android XR 套件的 Android OpenXR 功能，包括隱藏的生命週期掛鉤。Meta Quest Support、Touch Plus 及 Meta 手部追蹤繼續使用現有設定。
- 本機 Unity `6000.6.7f1` 的 Android 工具鏈位於 `D:\unity\6000.6.7f1\Editor\Data\PlaybackEngines\AndroidPlayer`，包含 SDK Build Tools 36、Platform Tools 37.0.1、NDK r27c、OpenJDK 17 與 CMake 3.22.1。Quest 建置會在內建 SDK 可用時使用它。

上一版 [Museum.apk](../Builds/Android/Museum.apk) 約 1,410 MiB，使用者回報 Quest 3 可安裝，開啟後停在黑畫面或三點。舊包同時帶有 Google Android XR 的必要裝置功能，建置報告也記錄了約 3.4 GiB 貼圖。若新版仍卡在同一處，接上已開啟 USB 偵錯的 Quest 3 後，用 `adb logcat` 擷取啟動期間的 Unity、OpenXR、AndroidRuntime 和記憶體訊息。舊版建置細節見 [Museum-build.log](../Builds/Android/Museum-build.log)。

2026-11-16 產出 [Museum-Quest3.apk](../Builds/Android/Museum-Quest3.apk)，版本代號 `2`，大小 752.01 MiB，較上一版減少 46.7%。建置前確認 189 張 ASTC 貼圖，建置報告中的貼圖從約 3.4 GiB 降至 835.4 MiB，網格維持 337.7 MiB。[新版建置日誌](../Builds/Android/Museum-Quest3.build.log)

- APK 的 v2 簽章、ZIP CRC、16 KiB 對齊和 ARM64 原生庫均通過檢查。簽章憑證與舊版相同。封裝僅含 Museum，且包含 Quest 3 的 VR 啟動宣告。
- 使用獨立建置專案的 Android 匯入資產執行 Unity Play Mode，9 項測試通過。Museum 成功載入並推進影格，主相機、四個互動展區及抽查的三個模型的 ASTC 材質均存在。Unity 仍回報舊版已有的大三角形碰撞網格警告。Quest 3 未連線，APK 的真機啟動尚待確認。[Play Mode 測試報告](../Builds/Android/Museum-Quest3.playmode.xml)
- `egyptian_styled_trim_set.glb` 的 `KHR_materials_specular` 與 UV 集合索引 2 匯入診斷在原專案已存在。該文物飾邊繼續使用原有網格與材質。
